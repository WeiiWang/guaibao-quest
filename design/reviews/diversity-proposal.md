# 乖寶任務「多樣性」擴充提案

日期：2026-10-27　性質：設計提案，未改任何程式。
依據：SPEC-v2.md、SPEC-v3.md、`src/learning/*`（types / chapter / select / skills / report / bank / sfx / speech）、`src/ui/screens/adventure/*`、`public/art/` 現有 84 張。

誠實聲明：
- 我沒有跑過 app，也沒看孩子實際玩的過程。時間估算是假設值，實作後要用 `Attempt.durationMs` 回頭校正。
- 教育價值的判斷依據是幼兒數學／語言發展的一般共識（一一對應、基數概念、空間語言、排序、工作記憶），不是針對本 app 的實測。我沒有逐篇重查文獻，所以不寫具體引用。
- 「重用現有素材」的做法（CSS 剪影、hue-rotate 換色等）我只從檔案清單推論，沒目視驗證，標「需驗證」。

## 0. 現況盤點（決定了哪些點子便宜、哪些貴）

- 題型：8 種（count / compare / diff / kind / color / odd / next / missing），全部是「題幹 + 選項卡 + 點一下」。互動只有 `onPick(choiceId)`。
- 題庫：3 技能 × 3 難度 × 42 題，固定 JSON，`items / choices / answer / hint` 的 schema 寫死在 `types.ts`。
- 一站 = 5 題，`planStation` 用技能輪替（2/2/1），5 站長得一樣，沒有站型差別。
- 阿悟（Companion）只用 6 個姿勢（idle/happy/cheer/think/sleepy/eating），但 `public/art` 已有 `pet-{baby,adult}-{sing,dance,laugh,shy,dizzy,sleep}` 沒在學習流程使用。這是零成本的情緒表現。
- 可重用素材：
  - 學習物件 10 個（obj-*）+ 食物 10 個（food-*）= 20 種可當「題目物件」；目前題庫只用前 10 個。
  - 家具 24 個（decor-*）可當「場景錨點」：桌、箱、帳篷、床、書架、火箭、恐龍……
  - 阿悟 12 姿勢 × 2 階段、仙石蛋、材料 3 種、UI 圖示 9 個、地圖背景 1 張。
- 資料層友善：`skillState` 以 skill 為主鍵、`getSkillStates()` 用 `SKILLS` 動態補預設值，所以新增技能不需升 Dexie 版本；`Attempt` 加 optional 欄位也不用升。章節進度 `Progress.stations` 長度取自 `ChapterDef`，加章節不破壞舊資料。
- 會被新題型卡到的地方：
  - `StageScreen.pick()` 內建 `choiceId === q.answer` 與「第二次錯標出答案」的流程，只適用點選。
  - `QuestionView` 依 `q.type` 分支渲染，沒有互動註冊機制。
  - `planStation` 只看 `SKILLS` 輪替，沒有「這個位置要出哪種互動」的概念。
  - `report.ts` 的 `LEVEL_LABEL: Record<SkillId, ...>` 會被 TypeScript 強迫補新技能。
  - e2e 腳本用 `data-testid="choice"`，新互動要自己訂 testid。

## 1. 設計前提：先做一個「互動框架」，不然每個新題型都要重寫流程

建議的最小架構（提案，不是已定案）：

- Question 加 `interaction` 欄位，預設 `'pick'`（舊題庫不用動）。新值：`'give-n' | 'drag-bin' | 'order' | 'place' | 'flip' | 'spot' | 'match' | 'rhythm' | 'listen-do' | 'story-order' | 'jigsaw' | ...`。另加 `params: object`（各互動自己的參數）。
- 每種互動是一個 React 元件，共同 contract：
  - 輸入：`{ q, hintStage, onWrong(), onSolved() }`
  - 輸出：由元件自己判斷對錯，呼叫 `onWrong()` 時 `StageScreen` 沿用現有的「第一次錯給提示、第二次錯標答案」階梯。
- 對應回現有計分：`firstTryCorrect = (錯誤次數 === 0)`、`hintsUsed = min(2, 錯誤次數)`。所以 `Attempt`、難度升降、報告、材料獎勵、複習排程全部不用動。
- `Attempt` 加 optional `interaction`（與 `taught?: boolean`）。用途：事後分析「是技能不會還是手不會」。
- 教學題（每個新互動第一次出現）：阿悟示範動畫 + 1 題引導，標 `tutorial: true`，不寫 `Attempt`（或寫但報告排除）。理由：4 歲的拖曳失誤是動作問題，不應該拉低技能難度。
- 所有拖曳都要有「點選再點目標」的替代操作（tap-to-place）。理由：4 歲手指精準度低、也是無障礙的底線。放置區最小 120px，吸附半徑要大。
- 「題目骨架 + 換皮」分離：同一個骨架（例：3 個東西排大小）在執行期把物件換成 20 種之一。這樣 JSON 每 (互動, 難度) 只需 6–8 個骨架，實際變化量是 20 倍。`scripts/gen-questions.mjs` 繼續產固定 JSON 供審閱，換皮在抽題時做（需確保換皮後仍合法，例如分類題的類別不能被換到衝突）。
- 站型模板（`StationTemplate`）：`ChapterDef.stations[i]` 加 `template`，描述這站的 beat 序列（見第 3 節），取代現在的「技能輪替」。
- 聲音依賴的互動（聽節奏、聽指令）必須有視覺備援：家長關音效或 Web Speech 不支援時，改成閃光 + 字幕，不能讓題目無法作答。

新增技能建議（共 6 項，家長報告從 3 列變 6 列，仍可讀）：

| 技能 id | 名稱 | 內容 | 難度 1 | 難度 2 | 難度 3 |
|---|---|---|---|---|---|
| number（既有） | 數感 | 擴充：拿給我 N 個、加減、分合 | 拿 1–5 個 | 拿 6–10、合起來 ≤5 | 加減 ≤10、分合 |
| classify（既有） | 分類 | 擴充：拖曳歸類、配對 | 一條規則 2 籃 | 3 籃或顏色 | 兩條規則（顏色 × 種類） |
| pattern（既有） | 規律與順序 | 擴充：聽節奏、故事順序 | 聽 3 拍複誦 | AAB 節奏、3 張故事排序 | 4 張故事排序、ABC 節奏 |
| space（新） | 空間 | 上下左右裡外前後、形狀、拼圖、方向 | 上下／裡外 | 左右前後旁邊、形狀 | 兩步指令、拼圖、方向路徑 |
| measure（新） | 比較與排序 | 大小、長短、高矮 | 挑最大／最長 | 排 3 個 | 排 4–5 個、用單位量長度 |
| observe（新） | 觀察與記憶 | 翻牌、什麼不見了、找不同 | 2 對翻牌、少 1 個（3 物） | 3 對、少 1 個（5 物） | 4 對、找 3 處不同 |

注意：難度是「技能整體」的階梯，同一技能內混多種互動時，各互動的 1/2/3 要用同一把尺校準（例如 number 難度 3 同時有「數 11–20」和「加減 ≤10」）。上線後用 `(interaction, difficulty)` 分組檢查正確率，偏離同技能平均 ±20pp 的重標難度。

### I1 ★ 拿給我 N 個
- 技能：number。年齡：4–6（難度 1 給 4 歲：1–5；難度 2 給 5–6 歲：6–10）。
- 互動：阿悟說「請拿 4 顆桃子給我」。桌上散放 8–10 顆桃子，孩子點一顆（或拖）就放進盤子，盤子旁邊同步顯示一一對應的格子與語音數數「一、二、三」。放完按「好了」（阿悟形狀的大按鈕）確認。放錯數量：阿悟「我們一起數數看」，盤子逐一亮起數，第二次錯時提示「再拿一個」或「拿掉一個」。
- 素材：0。物件用 `obj-*` / `food-*`，盤子用 `decor-crate` 或 CSS 圓盤。
- 複雜度：小–中。不需要真正拖曳（點即飛入盤子），可先於 DragKit 上線。
- 教育價值：高。現有「數一數選數字」測的是「說出數量」；「拿 N 個」測的是基數概念（拿出剛好 N 個並停下來），是早期數學的核心能力，選擇題測不到。也順便練一一對應。
- 注意：點數互動「點一個唸一個」要讓語音和動畫同步（`countAloud` 已有）。

### I2 ★ 拖曳歸類
- 技能：classify。年齡：4–7。
- 互動：畫面下方 4–6 個物件，上方 2–3 個籃子（標籤用物件圖示 + 文字，例如「水果」「動物」，或顏色色塊）。孩子把物件拖進對的籃子；放錯會彈回，並由阿悟提示「它是黃色的喔」。難度 3：兩條規則，籃子是 2×2（黃色水果／黃色動物／粉色水果／粉色動物）。
- 素材：0。籃子可直接用 `decor-crate`（箱子）加標籤；`OBJECTS` 已有 category + color 屬性可算正解。
- 複雜度：中。這是 DragKit（拖曳、吸附、彈回、tap-to-place、keyboard 替代）的第一個使用者，之後 I3/I7/I11/I12 共用。
- 教育價值：高。現有分類題是「找出一個」，這個是「主動歸類整批」，更接近真實分類思考，也自然帶出「同一個東西可以用不同規則分」。

### I3 ★ 排序：大小／長短／高矮
- 技能：measure（新）。年齡：4–7。
- 互動：
  - 難度 1：三個同款物件大小不同，點「最大的」「最小的」（其實還是 pick，但是新技能內容）。
  - 難度 2：3 個東西拖到 3 個格子，由小排到大（或矮到高）。
  - 難度 3：4–5 個；或「用貝殼量長度」——一根香蕉旁邊的貝殼鏈，數有幾個貝殼那麼長（非標準單位測量）。
- 素材：0。同一張圖用 CSS `scale`/`height` 做不同尺寸；長短可用 CSS 繪製的緞帶／棒子；高矮可用 `decor-lamp` / `decor-rocket`（本來就高）對 `decor-crate`。
- 複雜度：中（共用 DragKit）。
- 教育價值：高。比較與排序是數與測量的基礎，目前完全缺席。要避免的坑：大小要差異明顯（≥1.4 倍），否則會變成視力測驗；長短題要把兩端對齊，不然孩子會比錯位置。

### I4 ★ 空間方位（上下左右裡外）
- 技能：space（新）。年齡：4–7。
- 互動：場景是一個錨點家具 + 一個小物件，錨點用 `decor-table` / `decor-crate` / `decor-tent` / `decor-bed` / `decor-shelf`。
  - 難度 1（pick）：「小雞在桌子的哪裡？」選項是 3 張縮圖（上面／下面／裡面）。
  - 難度 2（place）：「把星星放到箱子裡面」「放到桌子旁邊」，拖曳到正確區域（區域判定用幾何，不需要新素材）。左右用「阿悟的左手邊」會讓孩子困惑，一律用「畫面的左邊／右邊」並在畫面上打記號。
  - 難度 3：兩個方位條件（「在帳篷的右邊、床的上面」）。
- 素材：0。
- 複雜度：小–中。pick 版幾乎是現有 QuestionView 換皮；place 版用 DragKit。
- 教育價值：高。空間語言（上下裡外前後）是幼兒期常見的數學預備能力；目前三技能完全沒有空間。位置詞要用繁中口語：「裡面、外面、上面、下面、旁邊、前面、後面、左邊、右邊」。

### I5 ★ 記憶翻牌
- 技能：observe（新）。年齡：4–7（2×2 → 3×4）。
- 互動：牌背用 CSS（馬卡龍色 + `ui-star` 當圖案），牌面用 `obj-*` / `food-*`。翻兩張，一樣就留著，不一樣就蓋回去。沒有時間限制、沒有步數倒數。
- 計分對應：「翻錯」不算 wrong（翻牌本來就會翻到不同的）。建議：翻牌次數超過 `對數 × 3` 時阿悟給一個提示（偷偷露出一對 1 秒），`hintsUsed` 才加 1。完成即 `firstTryCorrect = 沒用提示`。
- 素材：0。
- 複雜度：小–中（純前端狀態機，不需拖曳）。
- 教育價值：中–高。練視覺工作記憶與專注；但單看「配對成功率」會混入運氣，所以報告上不要寫成「記憶力評分」，只寫「專注與記憶的練習」。
- 注意：4 歲先給 2 對（4 張），不要上來就 12 張。

### I6 什麼不見了／找不同
- 技能：observe。年齡：5–7（「少 1 個」4 歲也可）。
- 互動：
  - 什麼不見了：顯示 3–5 個物件 3 秒 → 阿悟用手（或雲）蓋住 → 拿走 1 個 → 問「少了哪一個？」，選項是物件卡（pick）。
  - 找不同：左右兩個場景（同一組物件排列），右邊改了 1–3 處（換物件／少一個／變色），孩子點出不同處。
- 素材：0。「變色」用 CSS filter（hue-rotate）；需驗證不會把物件變得難看。
- 複雜度：小（什麼不見了是 pick 題 + 計時動畫）；找不同中。
- 教育價值：中–高（注意力、視覺比對、工作記憶）。

### I7 影子配對（連連看）
- 技能：classify / space。年齡：4–6。
- 互動：左邊 3 個彩色物件，右邊 3 個黑色剪影（亂序），從左拉線到對應的剪影。
- 素材：0（CSS `filter: brightness(0)`；透明背景 PNG 理論上可行，需驗證輪廓夠清楚）。
- 複雜度：中（要畫線；可退而求其次做成「拖到剪影上」，與 DragKit 一致）。
- 教育價值：中。練形狀輪廓的視覺辨識；同質性高，容易膩，建議當小遊戲而不是主力題型。

### I8 聽節奏、跟著拍
- 技能：pattern（聽覺版）。年齡：5–7（4 歲先 3 拍）。
- 互動：阿悟敲木魚／小鼓（WebAudio 合成，`sfx.ts` 已有 AudioContext），例如「咚、咚、恰」。每敲一下對應的圓點同時閃。孩子在畫面上兩個大鼓上依序點出來。判定看「序列正確」，不看毫秒精準度（容忍度大，避免 iPad 音訊延遲造成冤枉）。難度 2：AAB／ABB；難度 3：ABC。
- 素材：0（鼓用 CSS 圓形或 emoji 先頂）。如果之後想要質感，加 1 張鼓的 3D 圖。
- 複雜度：中（音訊排程 + 視覺同步 + 靜音備援）。
- 教育價值：中–高。把「規律」從視覺延伸到聽覺與動作，且是記憶序列。風險：Web Audio 在 iOS 必須由使用者手勢啟動；家長關音效時要自動改成純閃光版。

### I9 聽指令做動作
- 技能：space + 語言理解。年齡：5–7。
- 互動：只靠語音（附字幕）：「把紅色的蘋果放到桌子上面，再把星星放到箱子裡面。」孩子照做（拖曳）。難度 1 一步、難度 2 兩步、難度 3 兩步加兩個條件。
- 素材：0。
- 複雜度：中（TTS 品質與多步指令判定；DragKit 共用）。
- 教育價值：中–高（聽覺工作記憶、語言理解）。風險：Web Speech 唸繁中的品質因裝置而異，**不確定**孩子是否聽得清楚；字幕必須一直在，並提供「再聽一次」。

### I10 簡單加減／分合
- 技能：number。年齡：5–7（4 歲不建議）。
- 互動：
  - 合起來：「左邊 3 隻小雞，又來了 2 隻，一共幾隻？」兩堆動畫合併，選數字（現有 choices 可用，只是題幹動畫新增）。
  - 拿走：「5 顆桃子，猴子吃掉 2 顆，還剩幾顆？」物件飛走。
  - 分合：「7 可以分成 3 和幾？」拖物件到兩個盤子。
- 素材：0。
- 複雜度：中（題幹動畫 + 分合用 DragKit）。
- 教育價值：高，但對 5 歲以下可能太難，難度 1 只給「合起來 ≤5」並一律附動畫。**不確定**目標孩子目前的位置，建議先在 number 難度 3 之後解鎖，避免一開始就挫折。

### I11 故事順序（阿悟的一天）
- 技能：pattern（順序）。年齡：4–7（3 張 → 4 張）。
- 互動：3–4 張卡片打亂，拖成正確順序：起床（idle）→ 吃飯（eating）→ 玩耍（dance）→ 睡覺（sleep）。也可用 `pet-egg → pet-egg-crack → pet-baby-happy` 排「阿悟長大」。
- 素材：0（現有阿悟姿勢圖，其中 `sleep`、`dance` 已存在）。
- 複雜度：小–中（共用 DragKit）。
- 教育價值：中–高。時間順序、因果、敘事表達；也能請孩子「說說看發生什麼事」做親子延伸。要注意卡片敘事要明確唯一解，避免孩子合理的另一種排法被判錯。

### I12 拼圖
- 技能：space。年齡：4–7（2 塊 → 4 塊 → 6 塊）。
- 互動：把 `obj-*` / `decor-rocket` / 阿悟姿勢圖用 CSS 切成 2–6 片，拖回底圖輪廓。
- 素材：0（CSS `clip-path` / `background-position`）。
- 複雜度：中。
- 教育價值：中（部分—整體關係、空間推理）。偏好玩，作為「小遊戲」類型很適合。

### I13 形狀辨認與拼組
- 技能：space。年齡：4–6。
- 互動：圓、方、三角、長方、星、愛心（SVG 繪製）。難度 1：找一樣的形狀；難度 2：叫出名稱（語音 + 選）；難度 3：兩個三角形拼成方形（拖曳 + 旋轉，旋轉對 4 歲偏難，限 6 歲以上）。
- 素材：0。
- 複雜度：小–中。
- 教育價值：中。形狀名稱是常見的入學預備內容，但本身互動單調，建議與 I4 合併成 space 技能的一部分。

### I14 描線（筋斗雲路線）
- 技能：不在現有技能內（精細動作／書寫預備）。年齡：4–6。
- 互動：手指沿虛線描出直線、波浪、鋸齒、圓，描完阿悟的筋斗雲就沿線飛。
- 素材：0–1（雲）。
- 複雜度：中（路徑命中判定，iPad 手寫與捲動衝突要處理）。
- 教育價值：低–中。對書寫預備有幫助，但不是目前三技能的目標，也不容易自動判定「做得好不好」。放在好玩／動作發展類，不納入報告。

### I15 筋斗雲方向指令
- 技能：space（含序列思考）。年齡：6–7。
- 互動：3×3 格子，孩子按箭頭鍵排出「上、右、右」，雲照順序飛到桃子處。是最簡單的程式化思考。
- 素材：1（筋斗雲 3D 圖；或先用 `decor-cloudlamp` 去頭試）。
- 複雜度：大（序列編輯器、動畫、判定、題目生成）。
- 教育價值：中–高，但對 4–5 歲太難；可作為第 3 章（菩提山）的壓軸，非近期。

## 3. 章節規劃

世界觀（溫和改編）：阿悟是一隻想變得更厲害、保護朋友的小猴。沒有打鬥，所有「挑戰」都是解謎與幫忙。重要原則：
- 「大鬧天宮」「搶寶」等情節不用；龍王是愛收藏的老爺爺，阿悟是被請去幫忙整理的。
- 反派不出現，困難來自「天氣、迷路、不會」。
- 西遊記典故（水簾洞、筋斗雲、如意金箍棒、龍宮）當成故事裝飾，不要求孩子知道。

三個新技能的章節對應很自然：筋斗雲 → 空間，如意棒變大變小 → 測量，七十二變／找朋友 → 觀察與分類。

### 章節總覽

| 章 | 主題 | 新技能／題型 | 新素材（張，約 3 分鐘/張） | 章末事件 |
|---|---|---|---|---|
| 1 花果山（既有） | 認識阿悟 | number/classify/pattern pick 題 | 已完成 | 開寶箱 |
| 2 水簾洞 | 找到新家、大家一起住 | I1 拿給我 N 個、I2 拖曳歸類、I5 翻牌、I4 空間（pick 版） | 1（地圖；選配 1 張王冠） | 猴子朋友推舉阿悟當「美猴王」 |
| 3 菩提山 | 跟老師學本領 | I3 排序、I4 place 版、I6 什麼不見了、I8 聽節奏、I11 故事順序 | 約 3（地圖、老師、鼓或雲） | 筋斗雲試飛 |
| 4 龍宮 | 幫龍王整理寶庫 | I3 長短測量、I2 兩條規則、I10 加減、I9 聽指令 | 約 3（地圖、龍王、如意棒） | 龍王送如意棒 |

說明：章節順序照西遊記時間線（水簾洞 → 拜師 → 龍宮），新素材量恰好逐章遞增。若要在龍宮和菩提山互換，取決於想先給「空間」還是「測量」，沒有硬性依賴。

### 第 2 章 水簾洞（最少新素材版）

故事：下雨天，猴子朋友們沒有地方躲雨。阿悟聽說瀑布後面可能有個洞。阿悟深吸一口氣，跳進瀑布（水是溫的，不會痛）——裡面是一個又大又乾燥的洞。大家搬進來住，推舉阿悟當「美猴王」。

新素材（最少）：
- 必要 1 張：`scene-map-shuilian`（水簾洞地圖背景，16:9，沿用 `scene-map-huaguoshan` 的路線格式，POINTS 另設）。
- 選配 1 張：美猴王小王冠（沒有也行，章末改成阿悟 `cheer` + CSS 光環）。
- 其餘全部重用：
  - 瀑布水簾：CSS 漸層 + 動畫繪製（不用圖）。
  - 洞穴背景：CSS 深色漸層 + `decor-lamp` / `decor-cloudlamp` 點光。
  - 「猴子朋友們」：重用 `pet-baby-{happy,cheer,laugh,shy,dance}`，用 CSS `hue-rotate` / `sepia` 做 3–4 種毛色（需驗證效果，若不好看改成用不同姿勢 + 緞帶色塊區分）。
  - 籃子／盤子／石桌：`decor-crate`、`decor-table`、`decor-tent`。
  - 學習物件：把 `food-*` 10 個也拉進題庫（桃、蘋果、香蕉、葡萄、西瓜、牛奶……），即用 20 種物件，換皮就夠新鮮。
  - 材料：沿用木／石／花，不新增。

五站設計（每站見第 4 節的 beat 模板）：

| 站 | 名稱 | 主打 | 阿悟台詞（開場） |
|---|---|---|---|
| 1 | 瀑布前 | 教學站：拿給我 N 個（引導式） | 「好大的水聲！先幫我拿 3 顆桃子，我們帶給朋友。」 |

### 第 3 章 菩提山（學本領）

故事：阿悟想學會保護朋友的本領，爬到菩提山拜一位白鬍子的菩提爺爺為師。爺爺不講大道理，只出「功課」：每站學一個小本領。

## 4. 關卡內的節奏變化

### 4.1 站內 beat 模板

把「一站 5 題同款」改成「5 個 beat，形狀不同」。beat 種類：

| beat | 內容 | 時間估計（假設） |
|---|---|---|
| 開場 | 阿悟一句台詞（≤15 字、約 3 秒），與第 1 題同畫面出現，不另開一頁 | 3–5 秒 |
| 暖身 pick | 現有點選題，難度取目前等級 | 15–20 秒 |
| 主互動 | 本站主打的新互動（拖曳／翻牌／節奏） | 30–45 秒 |
| 挑戰題 | 該站最後一題，難度同等級 +0（最難的題型），失敗不影響材料 | 30–45 秒 |
| 小遊戲（選配） | 不計入 attempts 的 20–30 秒輕鬆遊戲（吹泡泡、接桃子） | 20–30 秒 |
| 結算 | 現有結算畫面 | 15 秒 |

站型：

| 站型 | beat 序列 | 約時間 | 出現位置 |
|---|---|---|---|
| 普通站 | 暖身 pick ×2 → 主互動 ×1 → 暖身 pick → 挑戰題 | 約 2 分鐘 | 大多數站 |
| 教學站 | 阿悟示範 → 引導題（不計分）→ 暖身 ×2 → 主互動 | 約 2.5 分鐘 | 每個新互動第一次出現 |
| 小遊戲站 | 暖身 ×2 → 主互動 ×2 → 小遊戲 | 約 2 分鐘 | 每章 1 站 |
| Boss 站 | 混合 5–6 個 beat，技能輪替，結尾有演出 | 約 3 分鐘 | 每章最後一站 |

總時長估算（假設值，待實測）：
- 每章 4 普通／教學站 × 2 分鐘 + 1 Boss 站 3 分鐘 = 約 11 分鐘，落在 8–12 分鐘內，上緣偏高。
- 若實測偏長：Boss 站拿掉暖身 pick，或每章改 4 站（3 普通 + 1 Boss）。
- 不要靠「站內題數」撐內容，靠「互動種類」撐內容，這樣時長不會膨脹。拖曳題每題比點選久（我估 2 倍），所以每站主互動最多 2 題。

### 4.2 Boss 站（不是打怪）

- 形式：守門人是「謎題」，不是敵人，例如水簾洞的「石頭老人」要大家證明會分東西才讓過。
- 機制：頂部有一條進度條，每答一題（不論提示與否）都前進，獨立答對額外亮星星；沒有血條、沒有扣分、不會失敗重來。提示階梯照舊。
- 結尾演出：阿悟 `dance` / `cheer`、全螢幕彩帶（沿用 `adv-confetti`）、材料多給 1 個；獨立答對率高時阿悟多一句誇獎，低時說「我們一起完成了」，兩種都是正向。
- 教學站與 Boss 站不要在同一個 session 連續出現兩次以上，避免疲勞。

### 4.3 連擊特效（只獎勵「自己想出來」）

- 連續獨立答對：
  - 2 連：題目卡周圍閃一圈光。
  - 3 連：阿悟 `dance` 兩秒 + 「三連擊！」。
  - 5 連（整站全對）：阿悟 `sing` + 結算多一個閃光。
- 中斷時什麼都不顯示（不說「連擊中斷」），只是計數靜默歸零。
- 取捨：連擊會鼓勵「不用提示」，但可能讓孩子不敢求助。緩解：提示用掉不扣任何東西；結算畫面仍用「跟阿悟一起想出來」的正向措辭（現有 `result-credit` 已是如此）。
- 這是純好玩項目，不影響學習判定。

### 4.4 阿悟的劇情台詞

規則：每句 ≤15 字，TTS 約 3 秒，同一句不連續出現，台詞庫分情境隨機取。同時用字幕顯示（現有 `adv-bubble`）。

| 情境 | 姿勢（現有素材） | 範例（每情境至少 3 句輪替） |
|---|---|---|
| 開場 | happy | 「今天要去哪裡呢？」「出發囉！」「我準備好了！」 |
| 教學示範 | think → happy | 「看我做一次喔。」「換你試試看。」 |
| 答對 | cheer / dance（連擊） | 「你好會想！」「哇，答對了！」「我也想到了！」 |
| 提示 | think | 「我們一起想想。」「再看仔細一點點。」 |
| 第二次錯／標答案 | shy | 「沒關係，我們看這裡。」「這個有點難，對吧？」 |
| 翻牌配對成功 | laugh | 「找到一對了！」「嘿嘿，記住囉。」 |
| 結算 | cheer / sing | 「這一站我們好棒！」「肚子餓了，想吃桃子。」 |
| 故事劇情（每站一句） | 視章節 | 「瀑布後面好像有光！」「老爺爺在看我們呢。」 |

零成本升級：`Companion` 的 `Pose` 型別補上 `sing | dance | laugh | shy | dizzy | sleep`（`companionArt` 已用 `pet-<stage>-<pose>` 規則，缺圖時退回 happy/idle，不會壞版）。

### 4.5 其他節奏變化（輕量）
- 站間「路上事件」：走到下一站的過場（2–3 秒）依章節換 CSS 動畫（飄雨、雲、氣泡），純視覺。
- 題目換皮：同題型在不同站使用不同物件組，避免「又是香蕉」。
- 每章主題色：地圖 mint → 水簾洞藍綠 → 菩提山暖橙 → 龍宮深藍，用 CSS 變數，不用新圖。

## 5. 每日變化

原則（硬規則，違反就不做）：
- 沒有連續登入獎勵、沒有連續天數、沒有「斷掉了」「今天還沒玩」提醒。
- 沒有倒數計時、沒有限時、沒有「限定」物品，所有收集物都能在一般遊玩中拿到。
- 沒有付費抽卡、沒有可購買的隨機獎勵；隨機獎勵不得與答對率掛鉤。
- 不做推播通知。每天玩多久由既有的家長「每日遊玩時間」控制，仍有「今天的冒險完成了」的自然結束點。
- 任何日常內容都是「可以不理它」的。

### 5.1 今日小主題（取代「每日任務」）
- 每天依日期固定產生一個主題（不是任務），影響當天選題偏向，例如：「圓形日」「紅色日」「數數日」「找朋友日」。
- 顯示形式：地圖上方一張小卡「今天阿悟想找：紅色的東西」。沒完成沒有任何後果。
- 實作成本低：只是 `pickQuestion` 的加權，不改計分。
- 取捨：是否讓孩子覺得「必須完成」？所以文案用「想找」而不是「任務」，不提供進度條。
- 好玩為主，附帶少量學習價值（讓主題內的重複練習自然發生）。

### 5.2 路上小驚喜（隨機事件，受控版）
- 內容：過站時，有機率遇到小事件，如「阿悟在路邊撿到一顆發亮的石頭」，帶出一個無計分的小動畫與 1 件收藏物（見 5.3）。
- 控制：
  - 一天最多 1 次，由「日期 + 站號」當種子決定（重開 app 不會刷新、不能靠重玩抽獎）。
  - 與答題成績無關（不是答得好才給）。
  - 物件價值低（貼紙／圖鑑條目），不給材料（材料維持穩定經濟）。
- 風險：任何隨機獎勵都有「變動比率增強」的成癮傾向。我們降低它的方式是上述三條；若仍覺得風險大，可全部改成固定位置的「彩蛋」（每章固定 1 個）。這點我不確定該取哪邊，建議你定奪。
- 好玩為主。

### 5.3 圖鑑「我認識的朋友」
- 內容：20 種學習物件（水果／動物／大自然／食物）+ 章節角色（猴子朋友、菩提爺爺、龍王）。孩子在題目中第一次遇到某物件並答對時，圖鑑多一張卡，卡片有圖、名稱、量詞、1 句語音小知識（「小兔愛吃胡蘿蔔」）。
- 呈現：未認識的顯示淡淡的剪影（用 I7 的 CSS 剪影）。不顯示「還差 N 個」，只顯示「認識了 12 位朋友」。
- 為什麼這樣設：靠自然遊玩集滿，沒有重複卡、沒有稀有度、沒有商店，避免收集癖壓力。
- 學習價值：中（詞彙、量詞、分類屬性的多次曝光；點開卡片可複習名稱）。同時是好玩的長期目標。
- 素材：0–1（圖鑑入口 `ui-album` 圖示，沒有就用 emoji 先頂）。
- 技術：新增 Dexie 資料要升版本，或把「已認識」存進現有 `settings` 的 optional 欄位以避免升版（v3 同樣原則）。

### 5.4 家長端「今日小提示」（現實世界延伸）
- 每天一則親子互動點子（家長端顯示，不進孩子畫面）：「今天吃飯時，請孩子數餐桌上有幾個碗」「在家找 3 個圓形的東西」。
- 價值：把螢幕內的概念轉移到真實物件，是最能提升學習成效的「每日變化」之一，零素材、零成癮風險。
- 可與現有的生活任務連動，但不強制。

### 5.5 日夜／季節外觀
- 地圖依真實時間 tint（早晨、傍晚、夜晚，CSS 濾鏡），沿用 v3 的 `getTimeOfDay`。
- 純好玩；零素材。

### 5.6 重玩變化
- 第二次玩同一章：同樣的站型，題目骨架換皮 + 難度依 `skillState`；Boss 站台詞換一版。這由 `Progress.run` 驅動，已有基礎。

## 6. 哪些多樣性真的提升學習、哪些只是好玩

判斷準則：該項是否讓孩子練到「現有選擇題練不到的認知能力」，或是否擴大了技能覆蓋面。

### 6.1 對學習成效有實質幫助
| 項目 | 為什麼 |
|---|---|
| I1 拿給我 N 個 | 測基數概念與一一對應；選擇題無法測到「停在剛好 N」。 |
| I2 拖曳歸類 | 主動歸類整批、多規則，比「找出一個」更接近真實分類。 |
| I3 排序／測量 | 新增完全缺席的比較與排序技能。 |
| I4 空間方位 | 新增完全缺席的空間語言與位置概念。 |
| I10 加減／分合 | 從「認數量」往「運算」前進；高價值但需看年齡。 |
| I11 故事順序 | 時間順序與因果敘事。 |
| I8 聽節奏、I9 聽指令 | 把能力延伸到聽覺工作記憶；前提是聲音可用且有視覺備援。 |
| 5.4 家長今日小提示 | 把概念轉移到真實世界。 |
| 教學站與示範 | 讓新互動的失誤歸因於認知而非操作。 |
| 圖鑑中的語音小知識 | 詞彙與量詞的重複曝光（效果中等）。 |

### 6.2 學習與好玩各半
| 項目 | 備註 |
|---|---|
| I5 翻牌、I6 找不同／什麼不見了 | 練專注與工作記憶，但成績混入運氣與動作，別當評量依據。 |
| I7 影子配對、I12 拼圖、I13 形狀 | 視覺辨識／空間推理，變化多但深度有限。 |
| 圖鑑收集 | 有詞彙價值，但主要是長期好玩目標。 |
| 今日小主題 | 讓重複練習自然發生，價值小。 |
| Boss 站 | 節奏上很有用，學習上等同「混合複習」。 |

### 6.3 主要是好玩（保留，但不要誤以為在提升學習）
- 連擊特效、阿悟情境台詞與新姿勢使用（但台詞能降低挫折，間接有益）。
- 路上小驚喜（隨機事件）。
- 描線 I14、筋斗雲試飛小遊戲、日夜／季節外觀、章節主題色。
- 章末演出（美猴王加冕、龍王送寶）。

### 6.4 多樣性本身的副作用
- 操作難度會混進認知難度（拖曳比點選難）：對策是教學題、tap-to-place、`Attempt.interaction` 欄位事後分析。
- 新技能資料不足時，家長報告會顯示「還不多」，這是正常的（`MIN_ATTEMPTS_FOR_VERDICT = 3`），不是 bug。
- 想驗證成效：凍結一組測試題（各技能各 6–8 題），開玩前、玩 2–4 週後各測一次，配對比較。每月樣本太少（個位數孩子），無法做 month-over-month 儀表板；單一孩子的資料只能看趨勢，別過度解讀。

## 8. 風險與待確認

- 風險：
  - DragKit 在 iPad Safari 的 pointer/touch 行為（捲動衝突、`touch-action`）需實機驗證；孩子試玩設備是什麼？
  - hue-rotate 換色猴子、CSS 剪影的視覺品質未驗證。
  - Web Speech 的繁中聲音品質因裝置而異；所有語音題必須有字幕與「再聽一次」。
  - 難度重新校準：新增互動之後，原有升降級（最近 5 題 ≥4 升、≤1 降）可能因互動難度不同而抖動。
  - e2e：現有 `scripts/e2e-adventure.mjs` 依賴點選 testid，新互動要補 testid 與新 e2e。
- 想請你確認：
  1. 孩子的實際年齡與目前表現（4 歲和 7 歲的設計差很多）；加減 I10 要不要現在做？
  2. 家長報告從 3 技能擴為 6 技能可接受嗎？
  3. 路上小驚喜（隨機）要不要做？我傾向做成固定彩蛋。
  4. 第 3、4 章順序是否按原著（菩提山 → 龍宮）。

## 9. 建議下一輪實作的 5 項（依投入產出排序）

估算為粗略人天（含測試，不含生圖），僅供排序參考。

1. **站內 beat 模板 + 阿悟台詞庫 + 連擊 + 補用 6 個已有姿勢**
   - 投入：小（約 1–2 天），0 新素材。
   - 為什麼第一：立刻讓 5 站不再長一樣；風險最低；同時為後面的新互動鋪好 `StationTemplate`。
   - 產出：`ChapterDef` 加 `template`、`Pose` 擴充、台詞表、連擊計數。學習價值低，好玩價值高。

2. **互動框架 + DragKit + 「拿給我 N 個」+「拖曳歸類」**
   - 投入：中（約 4–6 天），0 新素材。
   - 為什麼：框架是所有新題型的前提；這兩個互動分別補上基數概念與主動歸類，學習價值最高。
   - 產出：`interaction` 欄位、互動註冊、教學題機制、tap-to-place、`Attempt.interaction`、題庫新 JSON（各 ≥8 骨架 × 3 難度）、單元測試與 e2e。

3. **排序／比大小長短高矮（measure）+ 空間方位（space）**
   - 投入：中（約 3–5 天），0 新素材，靠第 2 項的 DragKit。
   - 為什麼：一次補上兩個完全缺席的技能，大幅擴大覆蓋面。
   - 產出：兩個新技能、`LEVEL_LABEL` 與報告、題庫。

4. **第 2 章水簾洞 + 記憶翻牌（observe）**
   - 投入：中（約 3–4 天）+ 1 張地圖生成，翻牌本身小–中。
   - 為什麼：把前三項的成果組成「看得見的新章節」，也是 PM 驗收最直覺的成果；翻牌零素材。
   - 產出：`MapScreen` 章節化（points/scene 進 `ChapterDef`）、章節選擇、第 2 章 5 站與章末事件、`observe` 技能。

5. **圖鑑「我認識的朋友」+ 今日小主題 + 家長今日小提示**
   - 投入：小–中（約 3 天），0–1 張圖。
   - 為什麼：提供長期的每日變化，且全部符合「無連續、無倒數、無付費」；家長小提示是學習遷移價值最高的低成本項目。
   - 產出：圖鑑畫面、已認識狀態儲存（避免升 Dexie 版本）、主題加權、家長端卡片。

暫緩：I8 聽節奏、I10 加減（待確認年齡）、I11 故事順序（第 3 章再做）、I15 方向指令、第 3–4 章、隨機驚喜。
